# Lab 01 — UI автомат тест (Playwright)

## Юу хийсэн
Би SauceDemo (https://www.saucedemo.com) дэлгүүрийн нэвтрэх хуудсыг Playwright ашиглан автоматжуулан тестэлсэн. Нийт 3 тест бичсэн: 
1. зөв нэвтрэх мэдээллээр амжилттай нэвтрэх, 
2. буруу нууц үгээр нэвтрэх үед алдааны мессеж гарахыг шалгах, 
3. нэвтэрсний дараа бараа сагслах ба гарах (logout) үйлдлийг гүйцэтгэх. Тестүүддээ орчин үеийн locator-уудыг (`getByPlaceholder`, `getByRole`) голчлон ашигласан бөгөөд сагсны тоолуур зэрэг тодорхой `data-test`/class шинжтэй элементэд `page.locator()` ашигласан.

Би windows үйлдлийн системийн WSL2 буюу windows-ийн Linux-д зориулсан дэд системийг татаж суулгасан ба түүн дээр Ubuntu гэх linux-ийн distro-г сонгосон. Code-оо бол Visual studio code-дээр бичсэн ба windows-ийн өөрсдийнхөн бүтээж гаргасан, дэд системд зориулагдсан wsl гэдэг extension-ийг суулгаснаар надад windows орчин дээр linux орчинд код бичих боломж бүрдсэн. Playwright-ийг windows-ийн powershell-ээр татах биш харин microsoft store дээр байгаа ubuntu-гийн terminal environment гэх app-аар татвал илүү зөв, учир нь powershell дээр татах гэж оролдвол зөвхөн windows-ийн npm ажиллах учраас дараа нь "npm init playwright@latest my-first-test" гэхэд шууд алдаа заадгийг ойлгосон. Playwright-ийг татчихаад tests гэдэг хуудсан дээр mytest.spec.js (би татахдаа javascript-ийг нь татсан юм) гэсэн файл үүсгэсэн ба тестээ бичиж эхэлсэн.

Хамгийн сүүлд гэхдээ github-руу өөрчлөлт үүсгэх болгондоо push хийхээ мартсан тул би алхмуудаа дахин нэг нэгээр нь хийж оруулсан буй.

## Ажиллуулах заавар
```bash
npm install
npx playwright install

```

## Playwright ба Selenium-ийн харьцуулалт (өөрийн ажиглалт)
Auto-wait функц надад цаг ихээхэн хэмнэсэн — элемент дэлгэц дээр бэлэн болтол Playwright өөрөө хүлээдэг тул `sleep()` эсвэл explicit wait бичих шаардлагагүй болсон нь код цэвэрхэн, богино болоход тусалсан. Codegen ашиглаж үзэхэд миний гараар бичсэн кодтой ерөнхийдөө төстэй байсан ч, codegen ихэвчлэн `getByPlaceholder` эсвэл илүү ерөнхий selector-уудыг санал болгодог тул зарим тохиолдолд `getByRole` эсвэл `data-test` attribute руу гараар заавал тохируулах шаардлагатай болсон. Trace viewer ашиглан алдааг шалгах үед маш ойлгомжтой байсан ба тест унасан яг тэр мөчид DOM snapshot-ыг харах боломжтой тул алдаа хаана, яагаад гарсныг шууд харах боломжтой. Selenium дээр үүнтэй адил дэлгэрэнгүй мэдээлэл авахын тулд өөрөө screenshot/лог бичих код нэмж оруулах шаардлагатай байдаг гэдгийг сурж ойлгосон. Locator-уудын хувьд `getByRole`/`getByPlaceholder` XPath-аас илүү уншихад амархан, HTML бүтэц өөрчлөгдөхөд эвдрэх магадлал багатай. Учир нь хэрэглэгчийн харж буй байдал дээр тулгуурладаг (жишээ нь товчны нэр, placeholder текст гэх мэт), харин XPath нь DOM-ийн бүтцээс шууд хамаардаг тул нэг элемент нэмэгдэхэд ч эвдэрч болзошгүй. Ерөнхийдөө цаашид тест хийнэ гэвэд Playwright-ийг илүү ашиглана гэж бодож байна, учир нь auto-wait, codegen, trace viewer гурав хамтдаа тест бичих болон дебаг хийх цагийг мэдэгдэхүйцээр хэмнэсэн.

## AI ашигласан эсэх (нэмэлт даалгавар, заавал биш)
Би AI (Claude)-г тестийн код бичихдээ шууд ашиглаагүй ч WSL2 орчин дээр `npx playwright codegen` ажиллуулах үед цонх хоосон/саарал өнгөөр гарч байсан тул асуудлыг шийдвэрлэхэд туслалцаа авсан. Асуудал нь WSLg-ийн GPU render хийх процесстой холбоотой байсан бөгөөд `LIBGL_ALWAYS_SOFTWARE=1` орчны хувьсагчийг тохируулснаар шийдэгдсэн. Мөн бичсэн 3 тестээ AI-д харуулж, trace viewer ашиглан алдаа санаатайгаар унагаж шалгах алхмуудыг хэрхэн зөв гүйцэтгэхээ зөвлөгөө авсан. Ингэснээр цаг хугацаа хэмнэсэн ч, тестийн логик, locator сонголт, assertion бичих зэргийг өөрөө хийсэн.
